# Color, contrast, accessibility, and inclusive design

- Preserve established color roles. Introduce a new color only when it has a clear semantic or compositional job and still belongs to the product.
- Check text and interactive contrast in actual rendered states, including focus, hover, disabled, overlays, and imagery-backed content.
- Keep semantic heading order, landmarks, accessible names, keyboard access, visible focus, adequate targets, meaningful alternative text, and reduced-motion behavior intact.
- Do not rely on color, motion, hover, pointer precision, or vision alone to communicate meaning.
- Prefer robust HTML and CSS over compensating ARIA. Validate with available automated tooling, then inspect the experience because automation is incomplete.

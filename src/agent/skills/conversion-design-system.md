# CTA clarity and design-system consistency

- Make the primary action match the visitor's likely next step and the promise immediately around it. Use concrete labels and honest expectations.
- Establish one primary action per decision point. Secondary actions may support comparison or escape, but must not compete without reason.
- Never use disguised ads, false urgency, confirm-shaming, hidden costs, forced continuity, misleading hierarchy, or obstructive opt-outs.
- Reuse existing components and tokens. If the requested result requires evolving the system, make the smallest reusable change and explain it.
- Check the implementation against the rest of the page so polish does not become a locally impressive but system-breaking one-off.

01 THE ROUTE

From rough intent to a concise outcome.

The happy path stays quiet. Roundhouse interrupts only when context, authority, or policy genuinely requires a person.

  1. DepotCapture the user’s original words and context durably.
  2. ClarifyAsk only when project, scope, safety, or authority is materially unclear.
  3. SliceResolve the project, decompose useful work, and preserve queue priority.
  4. ExecuteRun the configured executor inside a bounded local work area.
  5. VerifyApply operator-owned checks to the exact candidate that may ship.
  6. ShipUse the project’s explicit push or deployment provider.
  7. ReportReturn a compact, evidence-backed outcome.
02 THE BOUNDARIES

One control plane. Replaceable edges.

Roundhouse owns durable workflow, policy, questions, transitions, and evidence. Channels carry intent; runtimes provide capacity; executors change things; providers deliver them.

Channels

ChatGPT is first through a thin MCP/plugin adapter. Email and Slack are planned adapters, not separate workflow engines.

Runtime

One machine works without Herdr. Herdr is the later boundary for multi-machine coordination—not a prerequisite.

Human review

Project policy decides where work can proceed and where it must enter Needs You for clarification or review.

03 FIRST DEPARTURE

Run the complete local slice.

Current developer setup targets macOS, Node.js 20.11+, and Git. Installation creates the local front door and private state/configuration directories.

LOCAL SETUP
$ git clone https://github.com/ryngrn/roundhouse.git
$ cd roundhouse
$ npm install
$ npm test
$ npm run check
$ ./scripts/macos/install.sh
$ open http://roundhouse
$ ./scripts/macos/menu-bar.sh install
1

Configure a project

Copy an example autonomy configuration or use the control room editor. Set repository, context, checks, executor, and shipping policy.

2

Add a first task

Open http://roundhouse, describe the outcome in ordinary language, and add it to the Depot.

3

Watch the durable state

The background worker routes and executes ready work. The menu bar helper shows status and gives quick service controls.

4

Respond only when needed

If policy or missing context requires a decision, answer the revision-bound question in Needs You. Otherwise, work continues.

5

Inspect the outcome

Roundhouse reports checks, commit and branch evidence, and deployment results when the project is actually shipped.

04 CHATGPT STATUS

Polling everywhere. Same-thread events where supported.

UNIVERSAL FALLBACK

Manual status tools

get_work_status and get_needs_human work wherever the Roundhouse MCP tools are available. Ask ChatGPT for status when you want it.

SUPPORTED SURFACES

MCP Events

Subscribe a conversation to an item or project. Roundhouse sends Needs You, materially Blocked, and Shipped updates back to that thread. Progress is opt-in.

Current OpenAI support: Work chats on ChatGPT web; Work chats in the desktop app with Cloud selected; and dots. This is not a claim of universal mobile support.

05 CURRENT SIGNAL

Working now, and what remains ahead.

Roundhouse is an early public project. The line between implemented and planned is deliberate.

Working

  • Local browser control room and http://roundhouse front door
  • Menu bar status and service helper
  • ChatGPT MCP intake, questions, polling, and MCP Events callbacks
  • Durable local state, outbox transitions, restart recovery, and no silent replay
  • Background worker, project queues, configuration editing, and policy gates
  • Local execution, verification, Git shipping, and deployment-provider boundary
  • Automated unit and end-to-end tests

Roadmap

  • Email and Slack intake/status adapters
  • Herdr-backed multi-machine runtime and reconciliation
  • Remote/cloud workers and broader executor adapters
  • Pull request creation, merging, and richer delivery providers
  • Production MCP hosting, OAuth, and multi-user operation
06 OPERATING PRINCIPLES

Durable before clever

Intent, decisions, process boundaries, candidate commits, verification evidence, and delivery intent are persisted.

Failures stay visible

Interrupted or uncertain external actions become Blocked. Roundhouse does not quietly replay work it cannot prove safe.

Shipping is controlled

Models cannot inject verification commands or choose unconfigured delivery policy. Operators own those boundaries.

Noise is not status

Callbacks come from state transitions, never terminal logs. Default events are limited to human need, material failure, and completion.
